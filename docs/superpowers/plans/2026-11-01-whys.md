# Whys Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public Claude Code plugin `whys` that drills every build request into a closed statement file before planning, checks work against it during the build, and asks (never guesses) when something is missing.

**Architecture:** Two skills (`drill`, `check`) carry the method in short SKILL.md files with on-demand reference files. A SessionStart hook injects a few lines so the drill runs before any planning. A stdlib Python CLI (`whys`) does the mechanical parts (lint a statement file, plan coverage, miss log) so the skills spend little context.

**Tech Stack:** Claude Code plugin format (plugin.json, marketplace.json, hooks.json), bash, Python 3 stdlib (`unittest` for tests), `gh` CLI.

**Spec:** `docs/superpowers/specs/2026-11-01-whys-design.md`

## Global Constraints

- Repo: public `rj563/whys`, MIT license, installable via `/plugin marketplace add rj563/whys`.
- Plugin name `whys`; skills invoked as `/whys:drill`, `/whys:check`.
- Statement file path in target repos: `docs/whys/YYYY-MM-DD-<topic>.md`.
- Tags: `[owner]`, `[delegated]`; `✗` rejected; `✗ → S<n>` replaced; `?` open. No guess tag exists.
- Level 5 is a target, not a cap; file closed only when 0 `?`.
- Miss log is global: `~/.claude/whys/misses.md`.
- Never guess: ask unless the owner said "your call" for that item. "skip whys" aborts a drill.
- Dev-time questions: format confirmed in spec (task, touched statement, blocking questions only) + push notification.
- Each SKILL.md ≤ 120 lines; hook context ≤ 600 bytes. No Python dependencies outside stdlib.

## Review Focus

- Statement file with malformed lines (bad ID, missing tag, tabs vs spaces) → `whys lint` reports the line number, does not crash.
- Change file continuing numbering (S7 in a second file) and a `✗ → S7` in the first → lint across a directory treats IDs as project-unique, flags duplicates.
- Plan with a task citing no statements, or a statement cited by no task → `whys cover` lists both, exit 1.
- Miss log missing (first run, no `~/.claude/whys/`) → `whys miss` creates it; `whys kinds` on an absent log prints the default kinds only.
- Hook run outside a git repo / with no `docs/whys` → still emits valid JSON, exit 0.

## CLI contract (`bin/whys`, used by Tasks 2–4 and the skills)

- `whys lint <file-or-dir>` → stdout one line `status=<open|closed> depth=<n> open=<n> statements=<n>`; then one `L<line>: <problem>` per error; exit 0 if no errors, 1 otherwise. A directory lints all `*.md` in it as one project (IDs unique across files).
- `whys cover <whys-file-or-dir> <plan.md>` → lists `uncited S<id>` (live statements, not ✗, not cited by any task) and `task <N> cites nothing`; exit 0 if none. Tasks are `### Task N` headings; citations are a line `**Statements:** S1.1, S2` within the task.
- `whys miss <project> <statement-id> <kind> <note>` → appends `YYYY-MM-DD | project | id | kind | note` to `$WHYS_HOME/misses.md` (default `~/.claude/whys`), creating it.
- `whys kinds` → prints default kinds from `skills/drill/gaps.md` plus distinct kinds in the miss log, each with a count, most frequent first.

Statement line grammar: `^(✗ |\? )?S\d+(\.\d+)*  .+?( \[owner\]| \[delegated\])?( #\w+)*( → S\d+(\.\d+)*)?$`. `?` lines need no tag; all others need exactly one tag. Depth = number of ID parts. Child IDs require their parent to exist (in any file of the project).

### Task 5: drill skill

**Files:** Create `skills/drill/SKILL.md`, `skills/drill/format.md`.

SKILL.md frontmatter: `name: drill`, description starting "Use before planning or building anything new or any change…". Body must state, in this order:
1. Owner can say "skip whys" → stop.
2. Read project files first (README, existing `docs/whys/`, spec from brainstorming if any); never ask what they answer.
3. Create/extend the file per `format.md`; run `bin/whys kinds` for the checklist.
4. Level loop: one numbered batch per level in chat; owner answers by number in one message; write answers as statements; for each new statement run every kind; unanswered or new gaps → `?` lines → next batch. Unpack references into concrete confirm/reject items. Partly answered → stays `?` for the rest. Contradiction → old `✗ → S<new>`. Rejected parent → children ✗, listed in next batch for rescue.
5. Never guess; `[delegated]` only for exactly what the owner named.
6. Past level 5: continue, tell the owner which branches still produce questions.
7. Close: `whys lint` must report `status=closed` with exit 0; then one audit pass over the whole file for statements resting on something unconfirmed; then owner approves the file (edits allowed); commit it.
8. Handoff: if superpowers is installed, invoke writing-plans and tell it each task needs a `**Statements:**` line and that `whys cover` must exit 0 before execution; otherwise stop with the approved file.

`format.md`: the example file from the spec, the tag rules, the line grammar, the optional `Tags:` header line listing allowed `#tags`, and numbering rule for change files (continue after highest top-level ID in `docs/whys/`).

- [ ] **Step 1 (RED):** Dispatch a subagent WITHOUT the skill on scenario "Owner: build a lap-timing screen like in iRacing." Record whether it asks batched questions and unpacks "like in iRacing". Expected baseline: it proposes or asks a few unbatched questions.
- [ ] **Step 2:** Write SKILL.md and format.md.
- [ ] **Step 3 (GREEN):** Same scenario with the skill loaded and a scripted owner answer for level 1. Pass = numbered batch; a reference-unpacking list for "iRacing"; file written that `whys lint` accepts; no statement without `[owner]`/`[delegated]`.

### Task 6: check skill

**Files:** Create `skills/check/SKILL.md`.

Frontmatter `name: check`, description "Use before each build step when a docs/whys file exists…". Body states:
1. Read only the statements the task cites (`grep` by ID/tag), plus their parents.
2. If the step needs a decision they don't cover → don't guess. Main session: post one message in the confirmed format (spec section "How development-time questions are presented"), send a push notification (PushNotification tool) when available, continue other tasks that don't depend on it. Subagent: stop, leave work uncommitted, return `BLOCKED` with the questions in that format.
3. On answers: add child statements, drill them (drill skill level loop), `whys lint`, then `whys miss <project> <id> <kind> <note>` for each, then resume.

- [ ] **Step 1 (RED):** Subagent without skill, given a closed whys fixture and a task touching an uncovered decision; record that it guesses.
- [ ] **Step 2:** Write SKILL.md.
- [ ] **Step 3 (GREEN):** Same with skill: pass = no code for the uncovered decision; output matches the format; as subagent returns `BLOCKED`.
- [ ] **Step 4:** Commit `feat: check skill`.
